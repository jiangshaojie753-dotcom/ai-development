# Vocabulary Hub · IELTS Tracker V2

在导航中选择 Vocabulary Hub。可手动添加、编辑、删除、搜索生词 / 词组 / 难句，按分类、理解障碍和掌握状态筛选。学习数据仅在原浏览器本地保存，不使用新的数据库。

## 一次完整的使用流程

1. 添加英文原文、中文释义、来源科目；可补充英英释义、释义来源、词性、关键短语 / 难点、理解障碍、材料题号、例句解释、添加日期。输入已积累的单词会显示本机已有词义，点击所需词义填入；不同词义分别选择。柯林斯链接打开官网，当前不自动抓取官网释义。
2. 在难句卡片点击“提取词汇 / 词组”，填写提取出的内容。新卡保留原句关联，自动带入原句作为例句及来源。删除原句后关联仍可查看。
3. 在间隔复习中选择“英文回忆中文”“中文回忆英文”或“难句关键短语解释”。中文回忆模式用于单词 / 词组；难句解释模式要求填写关键短语。
4. 先回忆，再点击显示答案，提交“不认识 / 模糊 / 认识 / 熟练”反馈。刷新后进度保留。同一卡片每天最多一条正式复习反馈，避免重复点击虚增完成量。

## 掌握状态与日期规则

新卡从添加日期进入待复习，状态为未复习。反馈安排：不认识 → 1 天，模糊 → 2 天；认识 → 至少 4 天、上次间隔的 2 倍；熟练 → 至少 7 天、上次间隔的 2.5 倍。间隔四舍五入，上限 180 天。以用户浏览器的本地日期计算，跨月 / 闰日使用日历日运算。

连续两个不同日期反馈熟练才标为已掌握；其他反馈会回到学习中。已掌握的卡仍会安排后续复习。卡片内容分类、英文、词义或词性发生改变时增加修订版本，旧复习历史保留，但新内容重新计算掌握状态。修改备注、语境等不重置。

统计基于真实反馈：今日完成为当日去重卡片数；7 / 30 天曲线为各日完成卡片数；掌握率分母为当前未删除的该类卡片，分子为根据反馈达到掌握条件的卡片。没有卡片显示待积累，新导入卡片不会自动获得掌握状态。历史完成数保留后来删除卡片的真实复习；累计积累为当前未删除卡片数。

## 手写笔记与导入

支持电脑选择图片及手机拍照入口，JPG / PNG / WEBP，最大 10 MB / 4000 万像素。图片只用于本页临时对照：不会上传、持久保存或加入备份。刷新或点击清除会移除。

免费方案：用户自行将原照片上传到 ChatGPT，识别后复制 JSON 或 Tab 分隔文本到应用。无法辨认的内容请留空；在预览中逐条编辑、确认。每条都确认后才能保存整批；支持移除单条、取消整批。未确认前不写入学习数据。

JSON 格式（此例为虚构技术示例，不会自动载入）：

```json
{
  "vocabularyVersion": 1,
  "entries": [
    {
      "category": "word",
      "english": "sample",
      "meaning": "样本",
      "pos": "noun",
      "keyPoints": "",
      "reason": "unknown_word",
      "sourceSkill": "reading",
      "material": "虚构测试材料",
      "question": "",
      "example": "A sample is provided.",
      "explanation": "",
      "addedDate": "2000-01-01"
    }
  ]
}
```

也接受条目数组或 JSON Markdown 代码块。category 为 word / phrase / sentence；reason 为 unknown_word / unknown_phrase / listening / reading / grammar / other；sourceSkill 为 listening / reading / speaking / writing。必填分类、英文、中文、科目；日期缺省为确认当天。最多 500 条 / 2 MB。未知字段会报错，避免悄悄丢弃识别内容。空英文或中文可进入预览，但必须编辑补全才能确认。

纯文本每行使用 Tab 分隔：`分类<TAB>英文<TAB>中文<TAB>科目`。分类可填生词 / 词组 / 难句或英文枚举，科目可省略（默认 reading，预览中可改）。自由段落无法可靠分栏，需在 ChatGPT 整理成上述格式，不会自动猜测释义。

## 去重与来源

单词 / 词组按照分类 + 规范化英文 + 中文释义 + 词性匹配；不同词义或词性不会自动合并。两张卡都提供英英释义且释义不同，也分开保留；只有旧卡英英释义为空时才用新释义补充，历史语境中的空字段保持为空。保守匹配意味着表达不同但实际同义的中文可能形成多张卡，可人工检查更正。难句按完整英文匹配，同时保留各次不同翻译、关键短语和语境。

新增可选字段 `englishDefinition`、`definitionSource`、`meaningSource`（均为文本），支持批量导入、逐条编辑、JSON / CSV 导出和恢复。更改英英释义后重置当前掌握证据，旧复习记录仍保留；修改来源文字不重置。手动修改通过查词填入的释义，会在已有来源上追加“已编辑”。

柯林斯官方接入状态和申请说明见 [COLLINS_SETUP.md](./COLLINS_SETUP.md)。字段有值不代表已接入官方 API；来源必须如实填写。

相同卡片的来源科目、材料、题号、例句、解释、原因、日期、原句关联等作为出现记录保留。完全相同的记录重复导入不增加出现次数；不同日期或语境增加一次。修改卡片会保留原语境快照，但更正操作不增加出现次数；需要添加新语境时通过导入追加。删除为软删除，卡片退出日常列表与待复习，历史与关联仍保留在 JSON；再次导入同一卡片会恢复到列表。

## 兼容迁移与导出

原有 localStorage 键 `ielts-tracker:v1` 保持不变，内部数据 schemaVersion / 完整备份 backupVersion 升到 2；学习报告仍为独立 schemaVersion 1，无需修改原报告。读取旧备份 / 数据时补充空 vocabulary，不改变任务、训练、纠错、导入去重信息、阶段和复盘。首次写 V2 前在 `ielts-tracker:pre-v2` 保存旧原文，写入失败不覆盖主记录。V1 应用不能读取 V2 数据；升级时关闭旧标签页，勿回滚应用后继续写入。

“数据与同步”的完整 JSON 包括所有旧模块、词汇、关联和复习历史，仍能恢复 V1 备份（恢复 V1 会将词汇模块清空，替换前会下载当前完整备份）。Vocabulary Hub 的导出与恢复还提供仅词汇 JSON 备份，恢复前预览数量、确认替换并下载原词汇备份；其他模块不受影响。CSV 包含卡片、来源、关联、状态和下次日期，用于查看，不用作完整恢复。

原始迁移快照可以在浏览器开发者工具的 Application → Local Storage 中找到 `ielts-tracker:pre-v2`，复制到仓库外保存。所有个人备份应保存在仓库外。图片、私人 JSON、词汇 CSV 不会进入构建或 Git。

## OCR 扩展边界

`ocr.js` 提供依赖注入适配器，默认未配置会抛出明确错误，不发送网络请求，不伪装识别成功。未来只能通过有身份认证、大小限额的同源后端接入视觉模型；提供商 API key 保留在后端环境变量，禁止进入前端、localStorage、备份或 Git。识别结果必须进入当前逐条预览流程，不能直接写库。V2 不包含 OCR 服务或自动识别。

## 部署与验证

继续使用现有 IELTS Tracker checks and Pages 工作流。PR 运行语法、领域测试、构建检查；审核合并 main 后自动部署。静态白名单及 Service Worker 已包含新模块，缓存版本升到 v2，作用域仍仅为 `/ai-development/ielts-tracker/`。首次升级后关闭旧标签页再重新打开，离线缓存完成后可离线使用。

运行 `npm test --prefix ielts-tracker` 与 `node ielts-tracker/tests/browser-check.cjs`。V2 浏览器操作验收在 `tests/vocabulary-browser.cjs`，使用临时本地服务器、虚构数据，截图存入被忽略的 work/qa/。
